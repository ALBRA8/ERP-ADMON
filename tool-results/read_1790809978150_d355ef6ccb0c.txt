    74→====================================================================================================
    75→El software se compone del ejecutable principal y una serie de bibliotecas satélite que permiten
    76→su funcionamiento:

    78→1. Capa de Presentación e Interfaz de Usuario:
    79→   - Windows Forms (.NET 4.5).
    80→   - Componentes heredados de Shockwave Flash (Flash.ocx, FlashControlV71.dll, ShockwaveFlashObjects.dll)
    81→     usados históricamente para animaciones, gráficos interactivos o mapas visuales de mesas.
    82→   - Íconos y recursos embebidos en el propio ensamblado.
    83→
    84→2. Capa de Reportes e Impresión:
    85→   - CrystalDecisions.ReportAppServer.Prompting.dll y runtime de SAP Crystal Reports para Visual Studio.
    86→   - Impresión directa a puertos de impresora térmica POS (impresoras de comanda, tirillas fiscales).
    87→   - Dispositivos de impresión configurables por formulario y terminal (ParaLugImpre1, EmpImpTike).
    88→
    89→3. Capa de Integración DIAN y Servicios Web:
    90→   - Newtonsoft.Json.dll: Serialización y deserialización de estructuras JSON para comunicación
    91→     con API REST de proveedores tecnológicos y validación DIAN.
    92→   - QRCoder.dll: Motor de renderizado vectorial y matricial de códigos QR para la impresión en facturas
    93→     con el CUFE (Código Único de Facturación Electrónica), CUNE (Nómina) y URLs oficiales de la DIAN.
    94→   - System.Net.Http.dll: Envío sincrónico y asincrónico HTTP/HTTPS a endpoints SOAP de la DIAN:
    95→     * SendBillSync (Facturación Electrónica)
    96→     * GetStatus (Consulta de estado del documento en la DIAN)
    97→     * SendNominaSync (Nómina Electrónica)
    98→     * SendEventUpdateStatus (Eventos Radian / Título Valor)
    99→
   100→4. Capa de Infraestructura y Comunicaciones:
   101→   - Renci.SshNet.dll: Cliente SSH/SFTP para realizar transferencias remotas y copias de seguridad seguras.
   102→   - log4net.dll: Registro de eventos de auditoría y trazas de error del sistema.
   103→   - Google Mail / SMTP: Rutinas de autenticación para despacho de correos electrónicos con anexos (PDF + XML).
   104→
   105→5. Capa de Datos (Data Access):
   106→   - Módulo Hermes.Bconexion: Inicializa conexiones mediante ConnectionString ODBC ("DRIVER={MySQL ODBC 5.1 Driver};
   107→     SERVER=...; DATABASE=...; UID=...; PWD=...;").
   108→   - Utiliza objetos ADODB.Connection y ADODB.Recordset directos.
   109→   - Sentencias SQL dinámicas construidas mediante concatenación de cadenas en los módulos Botones,
   110→     BotGuarMa, Boteliminar, BotActualiza y Vardos.

   126→  * Hermes.BotGuarMa: Lógica de persistencia e inserción en base de datos de catálogos y maestros.
   127→  * Hermes.Boteliminar: Lógica de anulación reversa, borrado lógico y liberación de saldos contables,

   131→    validación de vigencias, resolución de listas de precios, cálculo de retenciones, amortizaciones y CUFE.
   132→  * Hermes.McxccpMov: Gestión centralizada del saldo de cartera (CXC / CXP).
   133→  * Hermes.MovOtros: Verificación de stock, trazabilidad de despachos, control de kits y parámetros de sistema.

   299→[BARRA DE HERRAMIENTAS Y ACCIONES DISPONIBLES EN CADA VENTANA]
   300→- Nuevo (Cmdnue): Habilita el formulario para capturar un nuevo registro.
   301→- Guardar (Cmdgra): Valida datos, genera el consecutivo y persiste la transacción.
   302→- Modificar (Cmdedit): Permite editar registros existentes si no están cerrados o transmitidos.
   303→- Eliminar / Anular (Cmdeli): Anula el documento y registra el motivo formal en tabla de auditoría.

  1348→9. DIAGNÓSTICO DE INGENIERÍA INVERSA: VULNERABILIDADES Y DEUDA TÉCNICA
  1349→====================================================================================================
  1350→Durante el análisis estático y dinámico de los binarios, código desensamblado y esquemas de datos,
  1351→se han identificado los siguientes hallazgos críticos de deuda técnica, obsolescencia y riesgos de seguridad:
  1352→
  1353→1. RIESGOS DE SEGURIDAD CRÍTICOS:
  1354→   - Almacenamiento de credenciales en texto plano:
  1355→     El archivo 'servidor.txt' en la carpeta de instalación almacena la dirección IP del servidor MySQL,
  1356→     el usuario 'root' y el nombre de la base de datos sin ningún tipo de cifrado. Cualquier usuario
  1357→     con acceso a la carpeta puede leerlo y conectarse con permisos de superusuario a la base de datos.
  1358→   - Inyección SQL masiva:
  1359→     Las sentencias SQL en los módulos BotGuarMa, Boteliminar y Vardos se construyen mediante concatenación
  1360→     directa de cadenas ("SELECT ... WHERE nit = '" & txtnit.Text & "'"). Esto hace al sistema altamente
  1361→     vulnerable a inyecciones SQL tanto accidentales (caracteres especiales como comillas) como maliciosas.
  1362→   - Uso de componentes ActiveX obsoletos y vulnerables:
  1363→     La inclusión de Flash.ocx y ShockwaveFlashObjects.dll representa un vector de vulnerabilidad grave.
  1364→     Adobe Flash fue descontinuado oficialmente y bloqueado en Windows por múltiples fallas de ejecución
  1365→     remota de código (RCE).
  1366→   - Ausencia de cifrado en tránsito:
  1367→     La conexión entre los terminales y la base de datos MySQL viaja a través del puerto 3306 sin SSL/TLS,
  1368→     lo que permite la captura de datos sensibles (salarios, transacciones, datos de clientes)
  1369→     mediante análisis de tráfico de red.
  1370→
  1371→2. DEUDA TÉCNICA Y LIMITACIONES DE ARQUITECTURA:
  1372→   - Conexión basada en COM ADODB sobre MySQL ODBC 5.1:
  1373→     El uso de la capa COM ADODB (.NET Interop) sobre un driver ODBC antiguo (5.1) de 32 bits introduce
  1374→     cuellos de botella severos, fugas de memoria por falta de liberación explícita de Recordsets
  1375→     y bloqueos de concurrencia cuando múltiples cajas POS facturan simultáneamente.
  1376→   - Ausencia de integridad referencial declarativa en el motor:
  1377→     Gran parte de las tablas de la base de datos fueron creadas bajo el motor MyISAM o sin restricciones
  1378→     FOREIGN KEY formales. La integridad referencial depende exclusivamente de que el código del formulario
  1379→     haga los borrados o actualizaciones en cascada. Si la aplicación se cierra de forma abrupta,
  1380→     quedan registros huérfanos e inconsistencias contables irreparables.
  1381→   - Monolito de interfaz gráfica acoplada a la lógica de negocio:
  1382→     No existe separación de capas (Arquitectura MVC, Clean Architecture o n-capas). El formulario
  1383→     WinForms contiene la validación visual, la lógica matemática y la ejecución de la consulta SQL
  1384→     directamente en el evento del botón. Esto impide reutilizar la lógica para crear una app móvil
  1385→     o un portal web sin tener que reescribirla por completo.
  1386→   - Dependencia pesada de SAP Crystal Reports:
  1387→     Los 109 reportes compilados en Crystal Reports exigen la instalación de runtimes pesados en cada equipo
  1388→     cliente, son lentos para exportar a formatos modernos y no se pueden visualizar en dispositivos móviles.
  1389→   - Mantenimiento y escalabilidad:
  1390→     El ejecutable principal pesa más de 37 MB. Cualquier cambio menor en una resolución o tasa de IVA
  1391→     exige recompilar y redistribuir todo el monolito en todas las terminales físicas de la empresa.

  1394→10. PLAN ESTRATÉGICO Y RECOMENDACIONES PARA EL NUEVO SOFTWARE MEJORADO
  1395→====================================================================================================
  1396→Con base en la ingeniería inversa realizada, se propone una estrategia clara para reconstruir y mejorar
  1397→el software SG Hermes en una plataforma moderna, escalable, segura y multidispositivo:
  1398→
  1399→FASE 1: DISEÑO DEL NUEVO BACKEND Y BASE DE DATOS (MIGRACIÓN DEL CORE)
  1400→1. Base de Datos Moderna:
